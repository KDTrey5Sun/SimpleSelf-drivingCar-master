极简版研究结构：Replay Buffer 与 Batch Size 对 DQN 的核心影响
════════════════════════════════════════════════════

主RQ(最终精简版):
  How do replay buffer capacity and mini-batch size jointly affect 
  sample efficiency and training stability in DQN for a dense-reward racing task?
  How do replay buffer capacity and mini-batch size jointly affect 
  sample efficiency, training stability, and computational throughput 
  in Deep Q-Learning for continuous control with dense reward shaping?

核心目标:
  只回答两个问题：谁更快收敛？谁更稳定？
  以最少实验与最少指标产出可复现、可解释结论。

────────────────────────────────────────────────────
一、实验设计(精简)
────────────────────────────────────────────────────
Phase A: Buffer 单维扫描 (sizes={1K,5K,10K,50K,100K}, 每个≥10 seeds)
  目的: 找到样本效率与稳定性较优的容量区间(中值 vs 极端)
Phase B: 二维 Grid (Buffer={5K,10K,50K}, Batch={16,64,128}, 每格3 seeds)
  目的: 验证联合效应 + 主效应方向 + 交互是否显著

总运行数量示例:
  Phase A: 5 × 10 = 50 runs
  Phase B: 3 × 3 × 3 = 27 runs
  合计 77 runs (可根据资源再降: 如 Phase A 降至 5×6=30)

────────────────────────────────────────────────────
二、采集指标(极简集合)
────────────────────────────────────────────────────
必须(Must):
  1. steps_to_target          首次达到 "success_count=100" 时的总环境步数
  2. episodes_to_target       同上对应的 episode 序号
  3. final_success_rate       最后窗口(最近100 ep)成功率
  4. final_avg_score          最后窗口平均得分
  5. success_curve            每 episode: success_rate_100
  6. td_loss_curve            每学习步或每N学习步平均 loss

可选(Optional, 若已实现):
  7. cv_success_rate          同配置跨种子 final_success_rate 的变异系数
  8. time_to_target_min       达到目标的 wall-clock 时间(分钟)
  9. episodes_per_min         吞吐量(整体速度侧描述性补充)

删除的内容:
  - 里程碑 25/50/75/90% 全集 → 不再记录
  - 斜率拟合(early/late) → 不再计算
  - Q值漂移 / 重用率 / 相关性机制 → 作为未来工作不实现
  - DTW 聚类 / 多稳态分析 → 移除

success_curve CSV 格式(单 run):
  episode,success_rate_100,avg_score_100
  1,0.00,123.4
  ...
  250,0.42,2310.7

run_summary CSV(聚合):
  buffer_size,batch_size,seed,steps_to_target,episodes_to_target,final_success_rate,final_avg_score,time_to_target_min

────────────────────────────────────────────────────
三、统计与判定(最小统计单元)
────────────────────────────────────────────────────
核心检验:
  Two-way ANOVA (Phase B 数据):
    因子: Buffer(3 levels), Batch(3 levels)
    因变量: steps_to_target
  若交互项 p<0.05 → 报告“交互显著”
  否则 → 报告“主效应显著,交互微弱”并给推荐组合

稳定性度量:
  对每个 buffer_size 计算:
    cv_success = std(final_success_rate_seeds)/mean(final_success_rate_seeds)
  目标: 中等容量(cv < 0.30) vs 极端容量(cv > 0.40)

不做的统计:
  - 多重比较校正(只关注最优 vs 次优即可)
  - 复杂回归/效应量/聚类

七、默认推荐配置(直接给出终稿可用)
────────────────────────────────────────────────────
快速起步:
  buffer_size = 10000
  batch_size  = 64
  epsilon_decay_mode = env_step
  learning_rate = 3e-4
  target_update: soft τ=0.005
  stop_condition: success_count >= 100 或 episodes >= 1000

表述模板 (写入论文):
  “Across 50 runs, a replay buffer capacity of 10K with batch size 64 achieved the lowest average steps-to-target (≈45K) and the smallest variability (CV ≈ 0.22), outperforming both very small (1K) and very large (100K) buffers.”

SRQ2 稳定性与方差
  Question: 缓冲区容量如何影响跨随机种子的训练结果波动 (run-to-run variability)?
  Hypothesis H2: 极小容量(快速覆盖) 与 极大容量(数据陈旧) 都提高方差; 中等容量方差最低。
  实现要点 (已在代码中完成):
    1. 在 Agent.learn() 中记录 TD 绝对误差均值/标准差 (last_td_mean, last_td_std)。
    2. Chapter3 & Chapter4 训练脚本收集 update_loss_history、td_mean_history、td_std_history。
    3. Summary 增加字段：
       update_loss_variance, update_loss_variance_last100, td_mean_last100, td_std_last100,
       learning_steps_to_first_success。
    4. plot_replay_sweep.py 新增：
       - 条形图：update_loss_variance / update_loss_variance_last100 / learning_steps_to_first_success。
       - CV(final_success_rate) 柱状图 (cv_final_success_rate.png)。
    5. analysis_variability_cost.py 输出 variability_table.csv：
       size, cv_success_rate, cv_avg_score, cv_avg_loss, mean_update_loss_variance, mean_update_loss_variance_last100。
  报告撰写：
    - 用 CV(success_rate) 对比 1K,5K,10K,50K,100K。
    - 引用 update_loss_variance_last100 说明后期稳定性差异。
    - 结论示例："10K 缓冲区在 50 次重复中表现最低方差 (CV=0.23)，验证 H2"。
\n+SRQ5 计算效率与成本-性能权衡
  Question: 不同容量的样本效率 (success_rate / first_success_episode) 与吞吐量 (episodes_per_min) 与资源占用 (mem_peak_mb) 间的权衡关系？
  Outcome: 绘制成功率 vs episodes_per_min 的 Pareto 前沿 (pareto_success_vs_eppm.png)。
  代码实现 (已完成):
    - Chapter3 记录 time_min, episodes_per_min, mem_peak_mb。
    - plot_replay_sweep.py 生成 success_rate 与 episodes_per_min 的散点 + Pareto (非支配) 标注。
    - analysis_variability_cost.py 输出 cost_pareto.csv 列出非支配点。
  报告撰写：
    - 用 Pareto 图识别 "同时高成功率+高吞吐" 的容量 (一般 10K 或 50K)。
    - 若 100K 有较高成功率但吞吐偏低 → 说明过大容量的边际收益下降。
\n+Batch Size 对 TD-Loss 方差与收敛的影响 (作为 SRQ2 延伸)
  添加字段：update_loss_variance / learning_steps_to_first_success (grid_summary.csv 中按 batch_size+size)。
